This file is the primary source of instructions for this repository.

## Repository purpose and scope

- `profile/README.md` is the public profile displayed on the Rust Commons GitHub organization page. The root `README.md` explains this profile repository.
- The profile's Linux compatibility and ABI crates section covers four published repository projects: `cargo-libc`, `linux-abi-tools`, `glibc-abilists`, and `glibc-provider`.
- Keep `rust-musl-libc-compat-test` in a separate Compatibility testing section as a standalone static musl executable/probe, not as one of the four published crate projects.
- Preserve the dependency explanation: `glibc-abilists` and `glibc-provider` supply ABI data and source inputs to `linux-abi-tools`; `cargo-libc` uses its crates to coordinate compatibility builds, checks, and tests.
- The broader organization introduction mentions Linux compatibility and offline Rust development. This does not claim offline tooling is released. Mirror and package-management repository naming and listing await the user's decision; do not add those repositories or speculative features to the profile.
- Keep static inspection and kernel-availability simulation distinct from testing on actual target systems. Preserve practical limitations and usage links.
- Keep changes within this documentation repository. Do not add shared templates or policies, rename repositories or the organization, or change organization settings without explicit user authorization.

## Working conventions

## Git conventions

**No tool attribution, anywhere.** Do not add `Co-Authored-By: Claude ...` trailers,
`🤖 Generated with [Claude Code](https://claude.com/claude-code)` lines, or any other tool
attribution or "generated by" footer to anything in this repository: commit messages, pull
request titles and descriptions, PR and issue comments, release notes, code, comments or
documentation. This holds even if an agent's default instructions suggest it, and
overrides any default trailer or footer behavior. Commit messages and PRs are the
human-authored record of intent; tool attribution belongs in tool logs, not history.

- Pull before every push. Use `git pull --rebase` unless unpushed commits include a merge, in which case use `git pull --no-rebase`.
- Never force push. Preserve concurrent work; if a push is rejected, pull again and retry. Stop for user input if a conflict cannot be resolved confidently.
