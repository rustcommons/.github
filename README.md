[profile/README.md](profile/README.md) is the public profile displayed on the
[rustcommons organization page](https://github.com/rustcommons). It states the
organization’s scope and introduces the Linux compatibility and ABI crates,
their dependencies, and a separate compatibility-testing executable.

Maintainers: follow the [documentation conventions](docs/DOCUMENTATION.md) and
use the [requirements index](docs/REQUIREMENTS.md) to trace this repository's
confirmed scope, documentation, and validation gaps. These are documentation
maintenance paths; this repository requires no build or runtime setup.

The dated [adoption record](docs/ADOPTION.md) tracks repository index revisions,
requirement counts, and remaining verification gaps.
Use the maintained [current release matrix](docs/RELEASE-STATUS.md) for delivered
versions, consumer adoption and outstanding release stages; the adoption record
remains historical.

Release-bearing projects follow the [release documentation convention](docs/RELEASING.md),
including user-facing changelogs, GitHub Releases and verification gates.

Read the [security policy](SECURITY.md) to report vulnerabilities privately and
verify releases; maintainers follow the [security baseline](docs/SECURITY-BASELINE.md).

Security reviewers: read the [disconnected-network assurance report](docs/SECURITY-ASSURANCE.md)
([PDF](docs/SECURITY-ASSURANCE.pdf)) and the
[proposed Best Practices answers](docs/BEST-PRACTICES-ANSWERS.md).
They distinguish released controls, bounded evidence and remaining gaps.
